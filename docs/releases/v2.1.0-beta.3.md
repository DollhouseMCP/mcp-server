# DollhouseMCP v2.1.0-beta.3

**Draft release preparation, updated 2026-10-22.** The release branch contains beta `d0278ad58d962a3386be34379475c40600c141a1`, the version preparation (#3127), and dependency remediation head `ccb4d8c82fef86550a0a4edba841ce750a1bd0dc` (#3129). Neither #3129 nor #3128 is merged into beta as of this review. These notes describe this candidate, not an announced release. Publication remains blocked on review, dependency integration and Safety publication. Database-backed memory remains dormant; hosted deployment and container-image qualification are separate.

#### Highlights

- **Clean dependency audits.** `npm audit` now reports 0 critical, 0 high and 0 moderate findings in three places: the root workspace, the standalone Safety package, and the qualified override-free consumer fixture using the exact local server/Safety artifacts. The pre-remediation beta baseline reported 38 high and 7 moderate, and Safety reported 36 high and 5 moderate. These counts are affected package entries, not separate advisories. (#3129)
- **Two vulnerable dependency chains removed.**
  - `gray-matter` pulled in `js-yaml` 3, then `argparse` 1, then `sprintf-js`.
  - `install-mcp` pulled in `giget`, then `tar` 6.
  - Both are replaced by small source adaptations: `src/security/frontmatter.ts` and `src/web/routes/clientConfigInstaller.ts`. Their MIT notices under `src/vendor/` ship in the package. Because the packages are gone, downstream installs no longer pull these chains either. (#3129)
- **Hosted sessions stay connected through quiet periods.** Standalone SSE sessions now get keepalive comments, a stream lifetime that tracks credential expiry, and idle grace after the last stream closes. (#3061)
- **Personas survive cache eviction.** Active personas are found again by their storage identity (file path or database UUID) instead of only by display name. (#3121)
- **Gatekeeper recovery stays reachable.** Infrastructure operations are classified before active-element policies are collected. If policy collection fails, the user gets an audited denial, not an approval. (#3126)

#### Breaking or behaviour changes

- **VS Code and Zed settings files that contain comments are no longer edited.** The setup installer now parses JSON strictly. If a VS Code `settings.json` or Zed `settings.json` contains `//` or `/* */` comments, the install refuses with:

  > Client config contains comments and cannot be updated automatically; file left untouched

  Add the DollhouseMCP entry by hand, or remove the comments and retry. (#3129)
- **Unparseable client configs are refused for all clients.** Previously they could be replaced. Writes are atomic, and dotfile-manager symlinks are kept. A dangling symlink is an error. Config files over 2 MB are refused. (#3129)
- **Supported install targets.** The installer covers Claude Desktop, Claude Code, Cline, Roo Cline, Windsurf, Witsy, Enconvo, Cursor, Gemini CLI, VS Code, Goose, Zed and Codex. LM Studio keeps its existing dedicated writer. It installs only the DollhouseMCP server: arbitrary command or URL installs, OAuth, project-local installs and downloads from `install-mcp` are not carried over. (#3129)
- **Front-matter parsing** keeps the parse, stringify and excerpt behaviour the server used, and still honours custom opening delimiters. Executable engines, filesystem helpers, sections and the global cache from `gray-matter` are not included. (#3129)
- **Standalone OAuth helper integrations.** The detached helper now needs a non-empty flow ID and matching prepared state. Setting the environment variable alone is refused before any shared writes or GitHub polling. Use `setup_github_auth` or its coordinated lifecycle. (#3116)
- **Hosted HTTP streams:**
  - MCP payloads are no longer delivered on a stream whose credential has expired. Heartbeats continue during renewal grace.
  - A stream is renewed only by an authenticated POST with a matching credential binding.
  - Messages dropped during expiry are not replayed. Renewal asks the client to resync its tool list.
  - (#3061)
- **Offline access in the embedded authorization server.** When offline access is requested, consent is added where appropriate. Refresh tokens still need client grant eligibility and user approval. Signed requests and `prompt=none` are not rewritten. (#3061)
- **Graceful replacement on hosted deploys:**
  - New mutations stop being admitted, and work already admitted is kept.
  - If drain or clean shutdown can't be confirmed, the replacement is refused.
  - Legacy `addEntry` replies now wait for persistence.
  - Update and rollback scripts send a nonce-bound drain acknowledgement before a single TERM.
  - This is drain-and-reconnect behaviour, not zero downtime.
  - (#3050, #3109)
- **Database memory is still dormant.** Tenant-bound database memory plumbing landed, with admission, conditional updates, fail-closed refusal of unsupported mutations and read-fidelity checks. It is **not enabled**. File-backed memory behaviour is unchanged. (#3012–#3043)

#### Upgrade notes

```bash
npm install @dollhousemcp/mcp-server@beta
npm install @dollhousemcp/mcp-server@2.1.0-beta.3
```

- Intended for the npm `beta` dist-tag only. No beta.3 publication has occurred; stable `latest` must remain unchanged.
- Requires `@dollhousemcp/safety` `^1.0.6`. Safety 1.0.6 must be on npm first.
- `gray-matter` and `install-mcp` are no longer dependencies. If your own code imported them through this package's install, add them to your own dependencies.
- If you use the setup installer with VS Code or Zed and your settings file has comments, expect the refusal above and add the entry by hand.
- Hosted operators can configure `DOLLHOUSE_HTTP_STREAM_KEEPALIVE_MS` (default 15000), `DOLLHOUSE_HTTP_STREAM_MAX_LIFETIME_MS` (default 0: no lifetime cap), and `DOLLHOUSE_HTTP_STREAM_EXPIRY_GRACE_MS` (default 300000). Values are milliseconds; zero disables that timer and nonzero values must be at least 1000. Credential-expiry payload gating remains enforced when the lifetime cap is disabled. (#3061)

#### Known issues

- **MCP SDK 1.32.0 age exception.** SDK 1.32.0 was published 2026-10-02T17:32:51Z. It is below the dependency-age policy until **2026-10-23T17:33Z**, when it reaches 21 days. It is the only approved exception, tracked in [#2452](https://github.com/DollhouseMCP/mcp-server/issues/2452#issuecomment-6327546083). If the release ships before then, it ships under that exception.
- **Safety 1.0.6 is not published yet.** Until it is, the consumer's `npm audit signatures` exits 1 (`ETARGET`) in the local packed-artifact check.
- **#3128 remains unmerged.** Its local build-info and fonts suites pass in CI; its two Docker runtime cases are skipped there and do not provide execution proof. All three Core OS jobs also contain nonblocking performance failures (119/120 each), despite successful job checks. See the PR’s qualification notes before integrating its separate memory changes.
- **#3129's audit result is reproducible for the exact packed artifacts.** It is not a guarantee about a fresh registry resolution. The consumer check relies on one reviewed parent version, `express-rate-limit` 8.5.1.
- The container image is hardened, but not every image advisory is resolved.
- Database-backed (guarded) memory is not activated. Provisioning, writer exclusion, capacity, backup/rollback and activation qualification are still separate prerequisites.
- **Three new installer reviews remain unresolved on #3129.** Generated runtime `npx` arguments omit `-y`, so a cache miss may prompt in a noninteractive client ([P1](https://github.com/DollhouseMCP/mcp-server/pull/3129#discussion_r4345332986)). VS Code/Zed JSONC comment refusal is an acknowledged regression under review ([P2](https://github.com/DollhouseMCP/mcp-server/pull/3129#discussion_r4345332995)). VS Code entries are written under `mcp.servers`, but status and NVM launcher/repair readers still inspect top-level keys ([P2](https://github.com/DollhouseMCP/mcp-server/pull/3129#discussion_r4345333005)). Previous green checks predate these findings; they are not resolved by documenting them.
- **The installer-execution fallback is removed.** `runInstallMcp` now calls the in-process config adapter and does not invoke the former on-demand `npx install-mcp` CLI. Generated server configs still use `npx @dollhousemcp/mcp-server@<version-or-tag>`; default `latest` is a moving tag and the missing `-y` issue above remains. Removal of `install-mcp` also removes its `giget` extraction chain.
