# DollhouseMCP v2.1.0-beta.3

**Private integrated qualification preview, updated 2026-10-28.** This source composes frozen beta `88efb60caedab9937dfe901c903b8e9132691cc9`, #3134 at `93e366e634633e6918fc7753726a8b39eec6b269`, the intended #3138/#3142/#3144/#3146 deltas, and isolated fixture/reporting/browser-runner repairs through `8f79134f11d820bca9a55b35d3122199e920b495`. Protected beta and the existing PR branches have not been changed. These notes describe the proposed combined source, not an announced or merged release. Safety 1.0.6 is published from `2d71c51b2a6cb4f499faf73695409f48835f6b1a`; a fresh registry metadata read confirms that version/source. Server publication, full platform/browser qualification, consumer provenance and hosted-image/deployment gates remain separate.

#### Highlights

- **Application security remediation incorporated in this preview.** #3134's exact runtime pins, browser DOMPurify copy, CLI-only Inspector closure and persisted client-config audit fix are present. On the combined Node20.20.2 Linux arm64 tree, the compiled custom source audit reports zero findings across 206 files and the production npm audit reports zero findings. Full development audit retains six LOW entries from the one explicitly accepted beta.3-only deepmerge advisory; it is not fixed or suppressed.
- **Exactly-full memory retention repaired.** Loading/manual enforcement no longer makes room for a nonexistent append; actual append still reserves one slot. (#3138)
- **Windows lock probing preserves the final rescan.** A 100ms reserve keeps owner-release observation inside the original 5-second budget without halving slow PID-reuse identity probes. (#3142)
- **Hosted proxy pin and CI preparation.** The intended Caddy 2.11.7 digest pin is present (#3144), with unchanged TCP ports; CI fixture budgets (#3146), fewer Safety-fixture Git startups, fail-closed audit reporting and a stable Ubuntu24.04 browser runner are staged. These are not claims that Windows/browser or hosted-image qualification has passed.
- **Two vulnerable dependency chains removed.**
  - `gray-matter` pulled in `js-yaml` 3, then `argparse` 1, then `sprintf-js`.
  - `install-mcp` pulled in `giget`, then `tar` 6.
  - Both are replaced by small source adaptations: `src/security/frontmatter.ts` and `src/web/routes/clientConfigInstaller.ts`. Their MIT notices under `src/vendor/` ship in the package. Because the packages are gone, downstream installs no longer pull these chains either. (#3129)
- **Hosted sessions stay connected through quiet periods.** Standalone SSE sessions now get keepalive comments, a stream lifetime that tracks credential expiry, and idle grace after the last stream closes. (#3061)
- **Personas survive cache eviction and failed restoration.** Active personas are found again by their storage identity (file path or database UUID); failed loads retain activation references instead of treating unreadable elements as deleted. (#3121, #3135)
- **Gatekeeper recovery stays reachable.** Infrastructure operations are classified before active-element policies are collected. If policy collection fails, the user gets an audited denial, not an approval. (#3126)

#### Breaking or behaviour changes

- **VS Code and Zed accept valid JSONC.** Setup preserves comments and unrelated settings, including custom environment text when updating existing entries. The exact runtime dependency `jsonc-parser` 3.3.1 supports these edits. (#3129)
- **Generated runtime commands use `npx -y`.** Noninteractive clients no longer stop for npm's package-install confirmation. Setup status, NVM launcher patching and startup repair recognize VS Code's nested `mcp.servers` entries. (#3129)
- **Unparseable client configs are refused for all clients.** Previously they could be replaced. Writes are atomic, and dotfile-manager symlinks are kept. A dangling symlink is an error. Config files over 2 MB are refused. (#3129)
- **Supported install targets.** The installer covers Claude Desktop, Claude Code, Cline, Roo Cline, Windsurf, Witsy, Enconvo, Cursor, Gemini CLI, VS Code, Goose, Zed and Codex. LM Studio keeps its existing dedicated writer. It installs only the DollhouseMCP server: arbitrary command or URL installs, OAuth, project-local installs and downloads from `install-mcp` are not carried over. (#3129)
- **Front-matter parsing** keeps the parse, stringify and excerpt behaviour the server used, and still honours custom opening delimiters. Executable engines, filesystem helpers, sections and the global cache from `gray-matter` are not included. (#3129)
- **Standalone OAuth helper integrations.** The detached helper now needs a non-empty flow ID and matching prepared state. Setting the environment variable alone is refused before any shared writes or GitHub polling. Use `setup_github_auth` or its coordinated lifecycle. (#3116)
- **Hosted HTTP streams:**
  - MCP payloads are no longer delivered on a stream whose credential has expired. Heartbeats continue during renewal grace.
  - A stream is renewed only by an authenticated POST with a matching credential binding.
  - Messages dropped during expiry are not replayed. Renewal asks the client to resync its tool list.
  - (#3061)
- **Offline access in the embedded authorization server.** When offline access is requested, consent is added where appropriate. Refresh tokens still need client grant eligibility and user approval. Signed requests and `prompt=none` are not rewritten. (#3061)
- **Graceful replacement on hosted deploys:**
  - New mutations stop being admitted, and work already admitted is kept.
  - If drain or clean shutdown can't be confirmed, the replacement is refused.
  - Legacy `addEntry` replies now wait for persistence.
  - Update and rollback scripts send a nonce-bound drain acknowledgement before a single TERM.
  - This is drain-and-reconnect behaviour, not zero downtime.
  - (#3050, #3109)
- **Database memory is still dormant.** Tenant-bound database memory plumbing landed, with admission, conditional updates, fail-closed refusal of unsupported mutations and read-fidelity checks. It is **not enabled**. File-backed memory remains the active storage path. (#3012–#3043)

#### Upgrade notes

```bash
npm install @dollhousemcp/mcp-server@beta
npm install @dollhousemcp/mcp-server@2.1.0-beta.3
```

- Intended for the npm `beta` dist-tag only. No beta.3 publication has occurred; stable `latest` must remain unchanged.
- Requires `@dollhousemcp/safety` `^1.0.6`. Its publication is recorded above; verify the registry artifact, provenance and clean registry-backed consumer before publishing the server.
- `gray-matter` and `install-mcp` are no longer dependencies. If your own code imported them through this package's install, add them to your own dependencies.
- VS Code and Zed settings may keep valid JSONC comments; malformed configs still fail without overwriting the file.
- Hosted operators can configure `DOLLHOUSE_HTTP_STREAM_KEEPALIVE_MS` (default 15000), `DOLLHOUSE_HTTP_STREAM_MAX_LIFETIME_MS` (default 0: no lifetime cap), and `DOLLHOUSE_HTTP_STREAM_EXPIRY_GRACE_MS` (default 300000). Values are milliseconds; zero disables that timer and nonzero values must be at least 1000. Credential-expiry payload gating remains enforced when the lifetime cap is disabled. (#3061)
