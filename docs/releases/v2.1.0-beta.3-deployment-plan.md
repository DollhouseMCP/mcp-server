## Gates and operands

1. Merge the reviewed `release/v2.1.0-beta.3` PR into **beta** and pass its required checks. Until that merge, **do not dispatch even the publish dry run**.
2. After merge, record the immutable beta release SHA and verify package.json, root lockfile version and manifest.json all say `2.1.0-beta.3`; generated build constants must agree. The version PR is not permission to publish.
3. Only after **Mick's explicit publish go**, invoke the real **Publish Beta Release** workflow, selecting `beta`, version `2.1.0-beta.3`, `dry_run=false`. Record the exact run ID/URL and wait for its publishers to succeed. No manual tag/npm/release shortcut.
4. Deployment is a subsequent, separately authorized operation after publication and deployment prerequisites are checked. A publish go alone does not execute the SSH commands below.
5. Before any host-changing step, confirm the actual deploy directory/Compose project, pinned SSH host key, current running container/image/source, current schema/migration state, restore-tested backup location, storage backend and portfolio obligations. These live facts are **unknown in this plan**. Do not assume beta.2 is currently deployed, or that a retained bundle is beta.2.
6. Confirm existing auth/admin/allowlist/OAuth callbacks and edge/cache configuration; preserve their secrets and settings. Do not bootstrap a different admin, open DCR, change SSH trust, rotate credentials or alter ingress policy as part of this update.
7. Current automation requires the **initially running** old container to support `org.dollhousemcp.memory-upgrade-drain=v2`, the private control-directory opt-in, writable root and no covering control-directory mount. If it cannot prove the drain acknowledgement and known clean closure, **stop**. No forced kill/restart-policy change, manual compose replacement or legacy-helper bypass. This may block an old beta.2 image; its actual capability has not been observed.
8. Qualify every migration between the actually deployed revision and beta.3. In particular, heed the runbook's 0045 pending identity-review and 0047 canonical-collision gates; 0048 credential revocation state may require explicit operator resolution. Never run a new app against an older schema. Forward migration, reverse application compatibility and any data-format conversion are separate decisions.

## Backup before deployment — future, after deployment go

Keep automatic wrapper backups enabled. On update/rollback it copies existing `.env`/`.env.production` with mode 0600 and writes a nonempty SQL dump under `<deploy-dir>/backups/pre-remote-<action>-<UTC>.sql`; a failed required backup aborts. Those local copies are **not encrypted off-host backups**, and `pg_dump` is a snapshot, not preservation of subsequent writes.

Before the update, an operator can create the runbook's encrypted DB/secret pair as follows. Supply distinct public age recipients from the existing backup policy and a new, safe path. This command is a **future SSH/server write**, not executed during preparation. Validate path/name operands contain only safe shell-path characters before passing them as SSH arguments.

```bash
: "${BACKUP_DIR:?new absolute restricted server backup directory}"
: "${DATA_BACKUP_RECIPIENT:?existing approved age public recipient}"
: "${SECRETS_BACKUP_RECIPIENT:?different approved age public recipient}"
[[ "$ALPHA_DEPLOY_DIR" =~ ^/[A-Za-z0-9_/-]+$ ]]
[[ "$ALPHA_INSTANCE" =~ ^[a-z0-9][a-z0-9_-]*$ ]]
[[ "$BACKUP_DIR" =~ ^/[A-Za-z0-9_/-]+$ ]]
[[ "$DATA_BACKUP_RECIPIENT" =~ ^age1[0-9a-z]+$ ]]
[[ "$SECRETS_BACKUP_RECIPIENT" =~ ^age1[0-9a-z]+$ ]]
test "$DATA_BACKUP_RECIPIENT" != "$SECRETS_BACKUP_RECIPIENT"
ssh -o StrictHostKeyChecking=yes -o "UserKnownHostsFile=$ALPHA_KNOWN_HOSTS_FILE" \
  dollhousemcp-alpha bash -s -- "$ALPHA_DEPLOY_DIR" "$ALPHA_INSTANCE" "$BACKUP_DIR" \
  "$DATA_BACKUP_RECIPIENT" "$SECRETS_BACKUP_RECIPIENT" <<'REMOTE'
set -euo pipefail
umask 077
D=$1; I=$2; B=$3; DATA_RECIPIENT=$4; SECRET_RECIPIENT=$5
command -v age >/dev/null
command -v gzip >/dev/null
test -d "$D" && test -r "$D/.env.production"
mkdir "$B"; chmod 0700 "$B"
cd "$D"
docker compose --project-name "$I" --env-file .env.production -f compose.yml \
  exec -T postgres pg_dump -U dollhouse dollhousemcp > "$B/database.sql"
test -s "$B/database.sql"
gzip -c "$B/database.sql" | age -r "$DATA_RECIPIENT" > "$B/database.sql.gz.age"
test -s "$B/database.sql.gz.age"
rm "$B/database.sql"
age -r "$SECRET_RECIPIENT" < .env.production > "$B/env.production.age"
test -s "$B/env.production.age"
# If filesystem portfolio/fallback state is authoritative, add a consistent,
# separately planned portfolio snapshot; do not call a live tar a no-loss backup.
REMOTE
```

Ship encrypted DB and encrypted secrets to the **separate existing stores** and confirm the recorded restore procedure/date before deployment. Their destinations and current access are unknown; do not substitute a guessed bucket. Back up a filesystem portfolio if it holds authoritative state; database-only mode may treat it as caches/fallback as described in the runbook. No secret rotation, admin change or allowlist rewrite is part of backup.

The remote wrapper clones **the verified tag** using `git clone --branch`, invokes its hosted helper, builds the application/migration images on the host, prepares the existing immutable PostgreSQL container, pulls the pinned Caddy version, drains/closes the old app, then runs migrations/grants and replacement. It does not take a raw commit SHA through `--ref`, and it does not offer a prepublished digest/pull-only deployment flag. Do not invent a GHCR beta.3 tag or pass a digest as a Docker build tag.

The new image ID is unknown until the supported build runs. Record the resulting immutable container ID and `.Image` ID, source revision marker, and successful authenticated beta.3 result below. Tags and prepared `server` directories may already change on a failed preparation; they are not proof that the running image changed. A failed migration/grant/bootstrap leaves the app stopped. A drain refusal leaves replacement blocked. Never automatically start the old app against changed schema, force stop, rerun migrations beside an undrained app, or treat readiness as a grant/auth check.

For an exact shell invocation from this VM, use the lockfile-installed SDK in `RELEASE_CHECKOUT` and an **already obtained**, private 0600 token file. This does not fetch a package, print a token, or automate GitHub/consent:

```bash
: "${MCP_TOKEN_FILE:?absolute private 0600 token file for an allowed hosted identity}"
export MCP_TOKEN_FILE ALPHA_PUBLIC_BASE_URL
EXPECTED_HOSTED_VERSION=2.1.0-beta.3 node --input-type=module <<'NODE'
import fs from 'node:fs';
import {Client} from '@modelcontextprotocol/sdk/client/index.js';
import {StreamableHTTPClientTransport} from '@modelcontextprotocol/sdk/client/streamableHttp.js';
const path=process.env.MCP_TOKEN_FILE;
const s=fs.lstatSync(path);
if(!s.isFile() || s.isSymbolicLink() || (s.mode & 0o077)!==0 || s.uid!==process.getuid()) throw Error('Unsafe token file');
const token=fs.readFileSync(path,'utf8').trim();
if(!token || /[\r\n]/.test(token)) throw Error('Invalid token file');
const client=new Client({name:'hosted-release-verification',version:'1.0.0'});
let failed=false;
try {
  await client.connect(new StreamableHTTPClientTransport(new URL('/mcp',process.env.ALPHA_PUBLIC_BASE_URL),{
    requestInit:{headers:{Authorization:`Bearer ${token}`}}
  }));
  const r=await client.callTool({name:'mcp_aql_read',arguments:{operation:'get_build_info'}});
  if(r.isError) throw Error('MCP tool failure');
  const outer=JSON.parse(r.content.filter(x=>x.type==='text').map(x=>x.text).join('\n'));
  if(outer.success!==true) throw Error('AQL read failure');
  const text=outer.data.content.filter(x=>x.type==='text').map(x=>x.text).join('\n');
  const match=text.match(/^- \*\*Version\*\*:\s*(\S+)\s*$/m);
  if(match?.[1]!==process.env.EXPECTED_HOSTED_VERSION) throw Error('Hosted version mismatch');
  console.log(`Hosted get_build_info version=${match[1]}`);
} catch { failed=true; console.error('Authenticated hosted build verification failed; no credentials printed'); }
finally { try { await client.close(); } catch { failed=true; } }
if(failed) process.exitCode=1;
NODE
```

Record successful hosted-version evidence alongside the immutable source/image IDs. Also follow the smoke test's read-only persona-list check and UI cache headers after update/rollback; ordinary `/ui/` and its content-versioned assets must retain `no-store` and not be a Cloudflare `HIT`. Unexpected auth changes, version mismatch, 401 with valid credentials, edge challenge, nonready state or unsafe logs are stop/recovery conditions, not success.

## Exact beta.2 rollback — two supported routes, no guessed selector

Rollback is **not automatic**. First close ingress through the existing reviewed maintenance control, preserve current state/new writes and take a **fresh** backup using the backup section with a new `BACKUP_DIR`. Require an operator-qualified beta.2 application versus current schema/data compatibility decision. The automation does not downgrade a database. A database restore would discard writes since that snapshot unless separately reconciled; do not restore a predeployment dump automatically. If the schema/data decision or maintenance mechanism is unknown, rollback is **blocked**, not improvised.

Use the **current reviewed beta.3 operator helper**, never the older beta.2 helper: beta.2's deployment code lacks the current drain ordering. The following future SSH script proves both requested tag identities and compares the complete newest retained bundle to an archive of beta.2. It uses Python 3 only for offline file hashing/comparison; require it to be present rather than installing it ad hoc. Confirm `SCHEMA_DATA_BETA2_COMPATIBLE=yes` and `ROLLBACK_INGRESS_CLOSED=yes` only from the actual approved operator decision/control, not to bypass a failed check.

```bash
: "${SCHEMA_DATA_BETA2_COMPATIBLE:?must be yes after compatibility qualification}"
: "${ROLLBACK_INGRESS_CLOSED:?must be yes after existing maintenance control}"
test "$SCHEMA_DATA_BETA2_COMPATIBLE" = yes
test "$ROLLBACK_INGRESS_CLOSED" = yes
# Revalidate ALPHA_DEPLOY_DIR/INSTANCE and full40hex RELEASE3_SHA before SSH.
[[ "$RELEASE3_SHA" =~ ^[a-f0-9]{40}$ ]]
ssh -o StrictHostKeyChecking=yes -o "UserKnownHostsFile=$ALPHA_KNOWN_HOSTS_FILE" \
  dollhousemcp-alpha bash -s -- "$ALPHA_DEPLOY_DIR" "$ALPHA_INSTANCE" "$RELEASE3_SHA" <<'REMOTE'
set -euo pipefail
D=$1; I=$2; EXPECTED3=$3
command -v python3 >/dev/null
WORK=$(mktemp -d /tmp/dollhouse-beta2-recovery.XXXXXX)
# Retain this work directory on failure; it is not deployment state.
git clone --depth 1 --branch v2.1.0-beta.3 https://github.com/DollhouseMCP/mcp-server.git "$WORK/operator3"
git clone --depth 1 --branch v2.1.0-beta.2 https://github.com/DollhouseMCP/mcp-server.git "$WORK/source2"
test "$(git -C "$WORK/operator3" rev-parse HEAD)" = "$EXPECTED3"
test "$(git -C "$WORK/source2" rev-parse HEAD)" = 7dc7cec3eb25d7fe2f3ccf2cff730113825ad57f
python3 - "$WORK/source2/package.json" <<'PY'
import json,sys
assert json.load(open(sys.argv[1]))['version']=='2.1.0-beta.2'
PY
mkdir "$WORK/expected2"
git -C "$WORK/source2" archive --format=tar HEAD | tar -xf - -C "$WORK/expected2"
PREVIOUS=$(find "$D" -maxdepth 1 -type d -name 'server.prev-*' -print | sort | tail -n 1)
ACTION=update
if test -n "$PREVIOUS" && python3 - "$WORK/expected2" "$PREVIOUS" <<'PY'
import hashlib,os,pathlib,stat,sys
def snapshot(root):
    root=pathlib.Path(root); result={}
    for directory,dirs,files in os.walk(root,followlinks=False):
        for name in dirs+files:
            p=pathlib.Path(directory)/name; s=p.lstat(); rel=str(p.relative_to(root))
            if stat.S_ISREG(s.st_mode):
                value=('file',s.st_mode & 0o111,hashlib.sha256(p.read_bytes()).hexdigest())
            elif stat.S_ISLNK(s.st_mode): value=('link',os.readlink(p))
            elif stat.S_ISDIR(s.st_mode): value=('directory',)
            else: raise RuntimeError('Unexpected retained bundle type')
            result[rel]=value
    return result
assert snapshot(sys.argv[1])==snapshot(sys.argv[2])
PY
then
  ACTION=rollback
fi
# Fresh DB/env backup must already have completed under this closed-ingress
# recovery operation; do not proceed merely because an old dump exists.
# Route A: exact newest retained beta.2 bundle -> supported rollback.
# Route B: otherwise supported update, staging exact source2 while executing
# current operator3 helper. SOURCE_DIR is the documented source-selection input.
DOLLHOUSE_HOSTED_DEPLOY_DIR="$D" \
DOLLHOUSE_HOSTED_INSTANCE_NAME="$I" \
DOLLHOUSE_HOSTED_SOURCE_DIR="$WORK/source2" \
DOLLHOUSE_HOSTED_GIT_REF=v2.1.0-beta.2 \
  bash "$WORK/operator3/scripts/hosted-deploy.sh" "$ACTION"
DOLLHOUSE_HOSTED_DEPLOY_DIR="$D" DOLLHOUSE_HOSTED_INSTANCE_NAME="$I" \
  bash "$WORK/operator3/scripts/hosted-deploy.sh" verify
REMOTE
```

Route A's `rollback` performs no schema downgrade; Route B's `update` runs the selected beta.2 migration code and current helper's grant preparation, so it requires that exact combination to be compatible before starting. Neither route permits a force stop when drain/closure is unproved, missing current admin/auth state, or an unknown/mismatched beta.2 source. A stopped current app cannot supply a live acknowledgement: retain state and use an explicitly assessed recovery procedure rather than starting it just to obtain one.

After either route, repeat strict public/authenticated checks above with `EXPECTED_HOSTED_VERSION=2.1.0-beta.2`, record the actual running image ID, and reopen ingress only after the chosen compatible state is verified. Route B must record `DEPLOYED_REVISION=7dc7cec3eb25d7fe2f3ccf2cff730113825ad57f`; Route A writes `rollback:<retained-bundle-name>`, so that marker alone is not a SHA proof—the full prior comparison plus actual beta.2 build-info result is required. Migration/grant/drain/build/proxy/verify failure leaves recovery held, potentially with prepared source/tag different from running state. Never delete volumes, reset the database, use `compose down -v`, or silently abandon postdeployment writes.
