# Dormant bounded database memory candidate handoff

This unit5 slice preserves existing-owner, archive-free UPDATE attempts before dispatch. It adds no production provider, activation, replay, operator recovery UI or permanent write history. The unit2 and unit3 dependencies, final enforcing-factory composition and cold qualification remain prerequisites.

The opt-in `createDurableAdmittedMemoryManager` starts closed. Its actual factory creates one virtual memory layer, gate, adapter and handoff store with the same database and dynamic server tenant resolver. The existing unconfigured composition stays unchanged and is **not** protected by this new protocol. The final protected profile must use the enforcing factory and exclude every other legacy writer. A trusted qualification callback is a composition seam, not evidence that current production eligibility, catalog, backup/restore, queue and cross-replica exclusions have already been established.

Each handoff retains the complete submitted candidate and metadata, original token, admission mode generation and captured server attribution. The bounded tagged data envelope preserves undefined versus omitted values, Unicode code units and unknown metadata keys without invoking accessors. Unsupported data fails before handoff or head dispatch. Limits are 262144 content code units, 10000 data nodes, depth40, and 1MiB per stored envelope including the eventual committed token. Stored content is tenant-private evidence and never appears in audit details. Inspection rechecks tenant and attribution after the awaited read before releasing candidate data.

Migration0061 provides forced-RLS candidate and quota relations. Quotas must be provisioned by privileged qualification; the application cannot create or reset them. A schema-owned trigger computes actual stored bytes, serializes accounting under a quota-row lock, validates counters against current retained rows and enforces 64 outstanding rows/64MiB per tenant. Runtime relation ownership is refused. Broad runtime CRUD grants cannot mutate quota counters, replace original candidate evidence, retire unresolved rows or supply an authoritative byte count. There is no TTL, unresolved eviction or automatic quota repair.

A gate-owned handoff transaction commits before a private process-bound receipt permits a head attempt. Unknown handoff completion closes local admission and never dispatches the head. Inside the existing head transaction, the original prepared row is locked and compared before CAS; the committed token is recorded atomically with head/tags/children. Only known enclosing COMMIT permits publication. A structural copy, restored row or old process receipt cannot supply authority. All retained candidates are consumed once, without stale-token refresh or replay.

`prepared` is conservative evidence: it may reflect a known refusal, an unresolved head result or no evidenced head dispatch. It must not be interpreted as proof that a write did not occur or rolled back. No separate best-effort refusal annotation is implemented here. A durable `committed` token records the atomic database result, but a lost outer completion still remains unknown to the original caller and closes its admission. Fresh evidence inspection does not automatically reopen it.

Retirement requires known head COMMIT and completion of the real owning application tail. Central save finishes cache/afterSave publication; immediate AQL defers retirement through its context/audit/response preparation; console UPDATE defers through the service's actual detail/ETag preparation. Nested manager saves cannot retire early. Failed tails retain committed candidates. Completed attempts are removed and release their slots atomically, allowing more than64 sequential successful saves. This is bounded outstanding preservation, not immutable historical snapshots or a remote transport ACK promise.

Lost retirement completion is observed separately as cleanup unknown. It never changes known committed/published success into head unknown, invents rollback, reruns the write or overwrites the original publication failure. The row may remain or already be retired; subsequent quota accounting uses actual stored rows. Throwing audit/log observers cannot replace the success facts.

Every boot starts closed; qualification is invalidated by close and unknown outcomes, including previously captured controllers. Retained rows prevent the provided fresh qualification seam from opening. The application receives no privilege to set durable mode to read-only. Cold promotion must drain/exclude already-started operations, queues, all processes and direct/admin writers; a local close cannot cancel an already-started write. Account deletion and backup/restore require their separate mandatory profile boundaries. Process-local pending maps alone make no crash-durability claim.

Focused controls cover exact encoding, getter refusal before adapter cloning, controller identity, candidate/context drift, original causes, no early publication and honest cleanup observation. Thirteen authored owned-PostgreSQL cases cover more than64 successes, actual central/AQL/console tails, full refused snapshots, quota isolation/concurrency, completion loss, post-handoff close, publication failure and replacement-controller refusal. Authored or locally skipped database cases are not execution proof: the actual required hosted assertions and cleanup must finish before merge. No migration, provisioning, restart or production activation is authorized by these tests or this document.
