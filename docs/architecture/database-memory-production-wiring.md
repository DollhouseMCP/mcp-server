# Database memory production wiring

This composition consumes the private tenant registry, authenticated operation provider, selected index view and real read-only boot qualifier. It does not establish deployment eligibility, authenticate manually constructed test contexts, exclude old writers or prove process restart. Actual authenticated two-runtime and compiled child restart qualification remains a separate deliverable under #2998.

## Startup and identity

`DatabaseServiceRegistrar` performs the always-executed application/system database admission check before selecting an ordinary factory. Durable protected state cannot be bypassed by disabling `DOLLHOUSE_DATABASE_MEMORY_GUARDED`. Configured composition validates the actual registry/application database, installs the sticky unattributed `Memory` fence, and selects the enforcing factory. Each tenant slot chooses immutable LEGACY or GUARDED composition only from its explicit durable tuple. Missing or unknown mode is never a legacy default.

Configured startup pages through durable tenant modes, resolves each exact tenant slot and invokes `qualifyDatabaseMemoryTenant` for guarded tenants before attributed startup reads. That qualifier performs the complete read-only snapshot census, catalog/quota/unresolved/foreign-row checks and actual captured-byte hydration predicate described in `database-memory-read-qualification.md`. Failure closes the registry. There is no fixture/no-op production qualifier, adoption, repair or live manager replacement. The durable factory continues to check the same fidelity predicate inside the admitted post-CAS transaction before committed handoff annotation.

Configured HTTP requires the existing authentication middleware and account identity mapper. The runtime callback receives verified claims, resolves the signed subject through the existing account link and validates its database UUID before creating the session. The provider pins that exact server-created subject; capture and every operation recheck require agreement with the authenticated ambient session and effective database resolver. Mutable activation overrides cannot change configured HTTP database authority. Configured HTTP set/clear identity helpers refuse before persona initialization or account lookup; ordinary local/stdio behavior remains. Deprecated identity tools are absent from the current production tool registries; this change makes no claim of an existing registered HTTP exploit.

## Caller and lifetime boundaries

Every configured operation synchronously captures the authentic tenant slot and immutable invocation/session primitives before its first await, waits on that exact initialization flight, rechecks the original context and retains one actual manager. No Promise substitutes for a manager, fixed root fallback, mutable current-binding field or mid-operation provider selection is used.

Configured Container and AQL construction structurally omit the fixed root memory manager and cached root index collaborators. After the original Gatekeeper succeeds, configured AQL constructs an invocation-local complete handler view. Capture/resolve before authorization performs only read-only mode lookup and inert construction; the registry rejects filesystem watchers before construction. Ordinary complete handler registries and call forms remain supported.

CRUD, activation, agent execution/continuation, console, EnhancedIndex, Collection, Portfolio and Sync use the authentic original operation. Agent state and nested memory reads retain the selected manager, use strict database listing and propagate the original configured failure through optional/group catches. Ephemeral AQL agent handlers share their parent's existing outer operation lock; the binding itself remains local. Non-memory and LEGACY operations retain existing behavior.

Console validates authenticated target UUID agreement before provider capture, binds one supported genuine store through lookup/update/serialization/ETag and owning completion, and retains the original operation on publication tails. Known committed publication failures retain their candidate/status; confirmed retirement is not later relabelled publication failure. Custom configured stores without the supported genuine contract refuse. One actual system database account-deletion boundary is shared by store, runner and module. Collection installation binds once before remote fetch and checks the same store through completion.

Selected derived indexes use the database memory source before filesystem discovery. Guarded indexes are genuinely RAM-only across locks, load/build, metrics, persist and disposal; explicit persist refuses. LEGACY indexes retain persistent behavior. Each view owns its caches/corpus/graph and releases its resources. Successful callers recheck original authority after awaited disposal immediately before result delivery; action failures preserve their original cause over cleanup failures.

Memory save records retain their actual manager, immutable original context and binding check through timers, failure probes, retry and flush. Replays restore/check the original context rather than borrow the flushing caller. Within the existing save owner, mutation-lock checks reread retained work before RAM changes/coalescing. Composed LEGACY clear refuses while retained sole-copy work exists. Parent-owned serialization is not a global or cross-parent/process drain.

The static memory fence is installed before attributed startup and console assembly. Genuine selected per-instance references remain available. Unattributed root/background/alternative startup routes refuse before fixed memory retrieval. Guarded startup skips unsupported seed CREATE, strictly lists existing qualified owners and retains the captured startup operation through autoload/activation. LEGACY and file startup behavior remains.

## Exact initial capability limits

The guarded profile supports existing-owner archive-free UPDATEs with the approved fidelity/policy predicate. CREATE, delete, archive and unsupported whole-owner mutation paths remain explicitly refused. Collection installation and bulk Sync preflight the complete discovered mutation set before any partial effect; unknown/ambiguous memory type does not silently skip the guard.

Existing remote submission/upload consumers require a local filepath. Selected guarded database memory therefore refuses that specific operation before filepath/authentication/remote effects; a UUID is never treated as a file. `get_element_details` and read-only console inspection are available inspection paths, not equivalent lossless export, remote submission or backup. Non-memory and LEGACY consumers remain available. Guarded not-found suggestions omit local memory files; non-memory and LEGACY suggestions retain their existing sources. Read-only guarded BOTH preflight freezes primitive decisions before any push effect; it does not change the existing ordinary/LEGACY push-only behavior of that route.

## SYSTEM shared memory

Configured shared-pool services use the already paired `SystemDatabaseInstance`. SYSTEM memory installation requires an explicitly provisioned `database`, protocol 1, `legacy-memory-writes-v1`, `legacy`, positive-generation tuple. The fixed SYSTEM owner is not a user-session UUID. A fixed-owner helper shares exact tuple validation without weakening ordinary UUIDv4 validation; the genuine privileged upsert transaction holds its `FOR SHARE` lock through settlement. Missing, malformed, GUARDED and read-only permission refuse before insertion. No runtime durable mode creation, default, promotion or repair is introduced; provisioning and cold exclusion remain operator prerequisites. Existing SYSTEM user-row provisioning is a separate FK prerequisite.

Non-memory shared seeds and ordinary unconfigured behavior remain. LEGACY managers retain existing public SYSTEM memory reads without attributing them as guarded qualification or tenant write authority. Guarded selected managers explicitly refuse public-memory inclusion before discovery/load and use owned qualified heads. The privileged writer boundary does not authorize arbitrary cross-owner tenant writes.
