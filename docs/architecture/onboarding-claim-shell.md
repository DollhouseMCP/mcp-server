# Invitation claim shell (unregistered)

`createOnboardingClaimPageRouter` handles only the fixed `/auth/onboarding/invitation` GET. It does not mount itself, write cookies, consume a credential, begin GitHub OAuth, activate an account, or create a normal session. Publish/mount only after the restricted API, proof-bound `/context` metadata reader, and complete GitHub/activation integration are ready together.

The first controller actions read the fragment into transient memory and replace browser history with the fixed clean path, before any network request. HTML is static and contains no account information or request-derived credential. No local/session storage, analytics, third-party scripts, fonts, images, or telemetry are used. The configured support contact is validated and URI-encoded separately around its single `@` delimiter.

Bootstrap POST obtains/rotates synchronizer CSRF. Only an explicit **Continue** click submits the credential to `/auth/onboarding/exchange`; duplicate clicks are blocked. Failure retries bootstrap/CSRF only and require a new explicit click to exchange again. An ambiguous response may be retried with the original same-owner binding through the existing API; the shell never invents a different owner. A newly opened fragment is not silently replaced with an already claimed session's account context.

After exchange, the controller clears its credential reference and reads `/auth/onboarding/context`. It expects the reviewed `OnboardingInvitationMetadata` projection: claimed state, account username/display name/verified email, intended roles, absolute invitation/session expiry and server time. It renders account values only through `textContent`, and uses the shared role descriptions for understandable access labels. Relative expiry derives from server time, not an invented client-side invitation lifetime. A conservative timer clears displayed metadata when the shorter server window elapses; the server remains the authority on every operation.

Page hiding aborts outstanding requests, clears memory references and account text, and ignores late responses. A restored page bootstraps again without automatically exchanging. Reload with a live restricted session rechecks metadata; an expired session requires reopening the newest email link. Logout uses the current CSRF POST and clears the page; ending the restricted session intentionally retains the stable owner binding as defined by the API.

The shell cannot yet distinguish expired, revoked, superseded, accepted or conflicting invitations from the API's neutral rejection. It therefore gives neutral newest-link/support guidance and temporary-outage guidance without an account existence oracle. Richer terminal-state copy requires a separately reviewed proof-authorized contract. The **Continue with GitHub** button remains disabled and honestly reports unavailability until the GitHub integration is connected; this slice does not pretend activation succeeded.

The exact shell response has a random per-response nonce for its own style/script, strict CSP, no-store, no-referrer, framing denial and nosniff headers. It ends via `res.end` because the embedded-AS `securityHeaders()` middleware wraps `res.send` and would otherwise reset script policy. Tests compose that real parent middleware and verify unrelated API responses still enforce `script-src 'none'`. Do not broaden global authentication CSP. The serialized browser function must stay self-contained; browser tests execute its actual compiled source, not a separate mock controller.

Validation covers nonce composition, explicit-click exchange, refresh, double-click prevention, text-only rendering, CSRF rotation/logout, neutral errors, late-response suppression and memory-only credentials. A real Chrome render check exercises the compiled shell with fake API responses, keyboard-only continuation, and desktop/mobile layouts. No real credentials or live email are used.

## GitHub connection

After a current proof-bound context read, the explicit GitHub button posts an empty body to `/auth/onboarding/github/start` with the rotated CSRF token. It never starts OAuth automatically. Only an HTTPS `github.com/login/oauth/authorize` response destination without userinfo or fragment can be followed. Before leaving, the controller clears its transient credential/CSRF values and visible account details. Pagehide aborts pending starts; late responses cannot navigate a restored page.

A failed start offers a fresh bootstrap; it does not replay claim exchange or OAuth start. The existing server-side GitHub state/session boundary remains authoritative. This slice does not register the page or routes.
