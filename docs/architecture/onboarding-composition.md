# Unregistered onboarding composition

`createOnboardingComposition` connects the reviewed invitation services on one PostgreSQL database and returns the restricted API router, exact-path claim-page router, and secured administrator module. It registers nothing in the application and performs no network requests while constructing them.

The caller supplies the trusted HTTPS public origin, support address, GitHub login client credentials, shared rate limiter, opaque-value service and administrative audit-key resolver. The callback is derived once from the trusted origin and used by both OAuth state and token exchange; request headers cannot select it. Portfolio integration credentials are not part of this contract. An explicit null email sender produces a manual-copy invitation; a real sender must enforce its own bounded transport timeouts and verified TLS.

All invitation, claim, session, metadata, OAuth state, activation and security/admin audit adapters share the supplied database. The same restricted-session authority protects metadata, OAuth state and activation. The factory creates no normal session: successful activation deletes restricted browser records and directs the browser to the existing ordinary console login.

The eventual guarded mount must register the admin descriptor with the secured console assembler, apply bounded JSON parsing there, and place the claim/API routers before generic body parsing, caching and sensitive request logging. Preserve the claim shell's route-specific nonce CSP, the API's script-none policy, TLS and the reviewed proxy policy. Callback queries and invitation bodies must be redacted at application and reverse-proxy boundaries. Database migrations, shared secret configuration, SMTP readiness, the GitHub callback registration, GitHub-required cohort policy and hosted acceptance remain release gates under #2684/#2460. This factory alone does not enable onboarding or authorize deployment.

The PostgreSQL HTTP journey constructs independent instances over shared storage, issues through the secured admin module, captures fake SMTP, exchanges on another instance, verifies state/PKCE through bounded fake GitHub clients, activates atomically, rejects callback replay, clears browser records and resolves a fresh ordinary login to the exact invited account. A separate account with matching provider email remains unchanged. Durable audits/storage and sanitized responses are checked for raw secrets. This is an HTTP/service integration test; real-browser and hosted-provider qualification remain additional layers.

The HTTP bootstrap resolves the explicit private-beta opt-in before any disabled-console early return. Enabled onboarding requires the shared hosted descriptor API, its normal production readiness and replacement evidence, the same database handle in concrete PostgreSQL authentication and rate-limit adapters, and the existing opaque/audit key services. Its admin descriptor is registered before manifest and secured-router assembly; only the claim-page and API routers leave the composition for the pre-parser transport slots. Missing dependencies fail startup without exposing either surface. SMTP verification runs only for explicitly enabled, complete SMTP configuration and returns a fixed sanitized startup failure. No deployment configuration or provider callback registrations are changed by this wiring.
