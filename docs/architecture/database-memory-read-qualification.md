# Guarded database memory read qualification

This focused source slice supplies the read predicate and trusted qualifier needed by #2998. It does not register a production provider, qualify a live cohort, admit tenants, provision quotas, stop writers or deploy. Production bootstrap/Container/authenticated caller assembly follows separately; actual signed-token two-runtime and compiled-child-restart qualification remains required.

## Shared read contract

The non-destructive predicate preserves authoritative raw YAML entry order, including valid equal-time entries, supported fractional JSON/YAML values and the actual loader's name normalization/defaults. It invokes the existing ElementLoader/MemoryManager transformation with load retention suppressed and creation/append effects suppressed. It does not initialize, seed, load storage, assign an admission token or publish a cache. Existing deserialize validation/quarantine diagnostics are not disabled. Authored data dropped or changed by that transformation refuses; absent instructions/extensions allow established defaults. Null/absent/ISO expiry forms follow the actual reader. Genuine archive references refuse; an absent or empty volumes list remains valid when no SQL volumes exist.

Numeric scalar checks wrap the pinned YAML numeric type construction per parse, retaining original resolve/tag behavior and original bounded scalar evidence. Decimal comparisons use a compact coefficient/exponent representation, without exponent-sized allocations. Bounded original JSONB user-number text is compared with its existing JavaScript representation; typed bigint revisions and database counters remain exact strings. Maintenance/apply eligibility is unchanged.

The durable factory binds its actual manager's predicate before exposing the composition. Its adapter checks the captured prospective candidate before handoff/CAS. After the genuine admitted parent/tag/child CAS, storage verifies the prospective raw and visible projection and repeats the same hydration predicate inside that exact transaction, before a prospective receipt, handoff committed annotation or outer COMMIT. A semantic failure rolls back and preserves the attempted candidate under the existing refused/unknown outcome contract. Ordinary LEGACY/non-durable composition remains unchanged.

## Must-run trusted boot checks

`qualifyDatabaseMemoryTenant` observes actual application/system database facts, a privileged effective observation role, known invalidation and mode/quota/handoff catalog contracts, the immutable protected mode tuple, provisioned counters and every retained handoff status. A missing, corrupt or unresolved condition refuses without reset, repair, replay, deletion or provisioning. Exact CHECK constraints and valid primary keys enforce the existing 64-row/64-MiB unresolved-candidate quota; these are not boot payload caps.

A single REPEATABLE READ READ ONLY system transaction enumerates the selected tenant by stable UUID keyset pages of 100 through explicit EOF. Each owner's bounded raw/projection and actual quiet hydration is checked then released; only the last key and count are retained. There is no 1,000-owner product limit or aggregate byte quota. Existing per-owner accepted-write bound is 256 Ki JavaScript string units, below the 2 Mi recovery bound. Query, scalar, graph and per-owner projection limits remain bounded; statement timeout/checkpoints refuse interrupted inspection. This is a complete finite snapshot census, not a universal startup latency promise. Final actual app/system identity observations occur after census settlement and before returning qualification, without holding one connection while acquiring another.

The privileged snapshot explicitly refuses selected-namespace foreign/orphan child/tag rows and archives before payload transfer. Ordinary runtime RLS cannot see hidden foreign rows. Verified invoker triggers, ordinary role/tenant binding, complete reachable route/direct-writer coverage and separately established privileged-writer exclusion preserve that invariant; this PR does not grant runtime system visibility.

## Proof and remaining prerequisites

Five targeted cases ran against owned local PostgreSQL17.10/ARM Podman with Node24.16: clean read-only qualification; dropped quota CHECK and extra domain-column refusal; privileged foreign-child refusal; actual durable save with fractions/tied order followed by fresh real qualification; actual synchronized-child INSERT corruption rolled back before COMMIT with unchanged full snapshot, no owning completion, exact retained candidate/handoff and original refusal cause. All assertions and cleanup completed. The trigger fault is controlled fixture SQL installed after real qualification, not a provider outage or production catalog attack claim. Numeric/actual-loader unit controls supplement those cases.

Fresh current-head hosted gates, real production registration, authenticated tenant/session routes, streaming deployment-envelope measurement, true compiled restart and accepted-write guarantees still require their own proof. READ ONLY/catalog success is not cold all-replica/request/account/admin/queue exclusion. Explicit mode/quota/grant provisioning, all-owner policy eligibility, backup/restore and protected read-only rollback remain operational prerequisites. No automatic adoption, dirty clearing, promotion, candidate eviction, archive UI or maintenance apply authority is introduced.
