# Local file-memory fence primitive

`FileMemoryFence.withFence()` provides bounded, cooperative exclusion for one memory locator on a local POSIX filesystem. It is a prerequisite for [version-checked memory writes](https://github.com/DollhouseMCP/mcp-server/issues/2870), not a persistence or archive store. No memory writer uses the primitive yet. It cannot prevent lost updates until every file-memory writer, including entry, clear, metadata, rollover, and erasure paths, participates and checks the durable head version under the same fence. The database backend needs its own transactional version check.

The caller supplies a tenant root and a relative memory locator. The root is canonicalized with `realpath`; existing locator components are checked with `lstat`, rejecting symlinks and hard-linked target files. A restricted lowercase ASCII locator namespace prevents unresolved case and Unicode aliases from getting different lock keys before the file exists. Dot aliases normalize to the same key. Callers must pass their actual canonical storage locator, not a display name or an independent slug. The tenant root and its ancestors must be trusted against concurrent filesystem replacement. This primitive is deliberately unsupported on Windows and does not claim safety on network filesystems with different `mkdir` or cache semantics.

An exclusive `mkdir` creates a private `0700` lease directory under `.memory-fences`; a random-token `0600` owner file is written and synced. Acquisition has a finite timeout. Release checks the directory device/inode and owner token before removing only that lease. A handled callback failure releases its lease; if release also fails, both errors are reported. A process crash leaves the directory in place, including a crash before owner-file creation. Neither age nor PID authorizes automatic stealing.

For a crashed lease, stop **all** writers for that tenant storage first. Confirm that no process can still own or acquire the fence, inspect the specific `.memory-fences/<hash>.lock` directory and any owner file, then remove only that lease directory and restart writers. Never remove a lease while writers run: inode/token checks cannot make an operator-initiated unlink and recreation safe against ABA races. Missing owner metadata is a reason to investigate, not evidence that the lease is free. This procedure covers process crashes; power-loss durability and multi-host coordination require separate validation before deployment.
