## Executable recipe and boundaries

Checksum-pinned BuildKit ADD instructions fetch the two official archives into an inert scratch stage; this introduces no executable base. The refresh RUN has network none and read-only input/source mounts. The existing24.21.0 container Node runs the helper; its CLI refuses other platform/version/architecture/user/executable paths. It requires original npm11.19.0 and exact regular-file/directory paths, refuses repeat receipts, streams and rehashes the exact-size archive before any extraction, then uses existing `/usr/bin/tar` with fixed arguments/clean environment/30s timeout/1MiB output to select only binary/headers into private staging. Archive hash identity plus retained immutable selected-member review is the extraction trust boundary; this is not a general untrusted-tar service. No new installer, package, mutable script or implicit executable fallback is introduced. BuildKit ADD checksum and readonly mounts are documented in the [Dockerfile reference](https://docs.docker.com/reference/dockerfile/).

The helper checks the staged paths are only expected files/directories, exact binary bytes/size and exact architecture header count/tree digest before replacement. It hashes the entire prefix before/after and fails if anything outside binary/headers changed, including npm core and CLI links. The receipt explicitly denies an official-image/npm11.19.1 claim and candidate execution by this helper. A failure after validated replacement fails the disposable Docker build layer; it is not a transactional host installer. The production CLI is restricted to the original root-owned container runtime; never invoke its exported test API against a host/global prefix.

The old base's binary remains in historical lower-layer bytes: only the active merged filesystem is refreshed. Do not claim every historical layer is free of old Node. Other installed/copy/archive paths, static library consumers, OS vulnerabilities, the independent offline-scanner Node runner and standalone CI Node24.21.0 are separate inventories/qualification scopes. Their pins and scanner exclusion/severity policy are unchanged. Actual image scan and applicability review must report residual findings honestly.
