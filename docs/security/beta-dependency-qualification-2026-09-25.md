For all eight exact candidates above, the downloaded npm tarball's computed SHA-512 matches registry `dist.integrity`, and the registry exposes one or two signature records. The npm `gitHead` of `browserslist@4.28.7` (`b637868`), `fast-uri@3.1.6` (`6f970b2`), `ip-address@10.3.1` (`be7e626`), and `js-yaml@3.15.2`/`4.3.2` (`5c45bd6`/`79ca68d`) matches the peeled release tag commit from the corresponding upstream Git repository. `brace-expansion` and `smol-toml` registry records do not carry `gitHead`. Manual source review found the `brace-expansion` 1.x and 2.x implementations rewritten from recursive tail expansion to an iterative accumulator with a 100,000-result cap and a 4,000,000-character accumulator cap. A safe 101-source merge input was accepted by both old parsers and rejected with `abnormal merge sequence size` by both candidates. Six ordinary YAML/frontmatter documents under DEFAULT, CORE, JSON, and FAILSAFE schemas produced identical old/new results for both major lines (24 comparisons per line). Large legitimate merge sequences or nesting may now reject; the application regression checks below exercise ordinary project inputs but do not prove full behavioral equivalence.
