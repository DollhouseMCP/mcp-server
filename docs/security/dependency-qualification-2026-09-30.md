# Nodemailer and brace-expansion qualification

Tracking [#2923](https://github.com/DollhouseMCP/mcp-server/issues/2923), on beta base `6c089cebe029833941419147220c815ccff641b2`. The September 30 user approval waives only the [21-day cooling rule](https://github.com/DollhouseMCP/mcp-server/issues/2452) for exact Nodemailer **10.0.9** and brace-expansion **1.1.21 / 2.1.7**. It is not an audit, command-permission, CI, merge or deployment waiver.

The previous baseline reported four high package paths (including inherited parent findings). Nodemailer 10.0.9 fixes the [address-parser denial of service](https://github.com/advisories/GHSA-v53p-9fqp-m79j) and recipient parsing changes; no patched 9.x release was available. Brace 1.1.21/2.1.7 fixes [nested recursion](https://github.com/advisories/GHSA-qhr7-859c-m2p7), [comma-parser recursion](https://github.com/advisories/GHSA-6j4f-fj2g-mc7p) and [quadratic rewrite](https://github.com/advisories/GHSA-q2hr-2g5m-vwhr). Exact brace overrides retain both major-version ranges in root and standalone safety packages. No broad audit fix or unrelated dependency upgrade is included.

## Artifact review

Downloaded old/new tarballs were inspected without execution and matched registry SHA-512. Candidate npm ECDSA signatures and upstream release-tag gitHead were verified. The [independent provenance review](https://github.com/DollhouseMCP/mcp-server/issues/2923#issuecomment-5914031329) verified Nodemailer SLSA using npm's bundled trusted verifier with explicit GitHub issuer/workflow identity: trusted root, DSSE signature, Fulcio certificate/CT, Rekor, and exact tarball subject. Tampered-payload and wrong-identity controls rejected. Brace advertises no provenance attestation. These observations do not prove absence of publisher compromise.

Brace artifacts change only index.js and package version, with no dependency, lifecycle-hook or engine changes. Nesting/rewrite limits default to 1,000 and leave remaining syntax literal; they do not establish that every arbitrary glob has bounded cost. Application permission matching does not use brace expansion; source CodeScanner does use glob, so its normal inclusion/exclusion behavior is qualified separately. Independent bounded checks passed ordinary nested/chained/range/rewrite behavior, literal-remainder limit semantics, and minimatch 3.1.5 / 9.0.9 inclusion/exclusion on the installed fixed leaves.

Nodemailer has no runtime dependencies or preinstall/install/postinstall hooks. The new prepare/build script is not executed during scripts-disabled installation; published compiled ESM/CommonJS output and declarations are present. Node minimum rises to 20, matching the application. SMTP/DNS/TLS, MIME and parser changes make this a major compatibility qualification, not a trivial patch.

## Compatibility checks

Real installed stream serialization covers normalized single recipients, multipart output, and file/HTTP/HTTPS access tripwires. Ephemeral loopback-only SMTP tests cover rejected or unadvertised STARTTLS before AUTH/DATA, untrusted implicit TLS before SMTP commands, greeting timeout, and rejected authentication over verified implicit TLS. No real messages or external SMTP are used.

Local Node 24 ESM/default, CommonJS createTransport and legacy mail-composer/index.js / stream-transport/index.js exports passed. Strict compiler tracing with the repository's `moduleResolution: node` resolves the root to bundled 10.0.9 declarations and explicit deep index.js imports to retained @types/nodemailer 8.0.0. Those deep imports still rely on @types; removing it is not part of this change. The extended compatibility workflow automatically builds/tests beta PRs on Node 20 and 22 across Linux, macOS and Windows; its exact-head results remain a merge gate.

Local normal precommit, full lint and production build passed. Root audit reports 0 high/critical, 19 moderate and 1 low; production-only audit reports 11 moderate; standalone safety reports 1 low. Installed signature verification passed for 1,310 packages and 113 attestations. Existing SMTP/invitation tests passed 220 cases, the new actual-transport suite passed 5, policy/CodeScanner suites passed 254, and standalone safety passed 79. Full unit passed 666 suites / 15,029 tests with 1 suite / 9 tests skipped, but the unchanged BuildInfo parallel timing assertion failed at 2,401 ms versus the 1,000 ms local limit. One authorized isolated diagnostic also failed at 1,669 ms (20 other cases passed). Both original results are preserved in [#2927](https://github.com/DollhouseMCP/mcp-server/issues/2927); no threshold or environment adjustment and no further retry. The candidate is **not fully qualified**: causal evidence and final-head CI/reviews remain required before merge. Existing low/moderate findings stay tracked separately in [#2837](https://github.com/DollhouseMCP/mcp-server/issues/2837). No deployment or production email is authorized. Rollback to prior pins retains their known vulnerability exposure.
