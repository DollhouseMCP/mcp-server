## Capture boundary

Prefer trusted Docker filesystem materialization over a new custom OCI overlay implementation. Reuse the already exported target archive and `verify_saved_image()` proof from `scripts/scan-built-image.py`. A separate helper, run after that step with `always()` on AMD64, must revalidate archive SHA/typed graph against the currently inspected exact target storeID. Never equate manifest/index/config IDs. It records the job head/run/attempt, image architecture, selected descriptor/config, ordered layers, source label and archive digest. Exclude image Env values from retained inspection.

Then create one uniquely named temporary container using the exact verified storeID, `--pull never --platform linux/amd64 --network none --read-only --no-healthcheck --cap-drop ALL --security-opt no-new-privileges --user 65532:65532 --entrypoint /bin/false`. The container MUST NEVER BE STARTED. Inspect before/after export: exact `Image` store role, exact `Config.Image` argument, selected `ImageManifestDescriptor` where applicable, `State.Status=created`, `Running=false`, `Pid=0`, zero start time/restarts, no bind/device mounts and no image-declared volumes. Any mismatch makes capture unavailable. The override user is capture containment; separately retain the image's original Config.User. It is not evidence of production deployment privileges.

Use `docker export <exact-created-ID>` as a bounded stream to private runner temp, not reports. This exports the daemon's merged rootfs after whiteouts, without target programs. Bind export SHA256/byte count/command/time/exit to the exact graph and container observations; trust in the reviewed Docker daemon's snapshot/export implementation is explicit, rather than claiming the rootfs tar hash is an OCI layer digest. Remove only this exact container in `finally`; record cleanup failure and stop. No `run`, `start`, `exec`, `ldd`, loader, target shell, target Python/Node, package manager or target-provided inventory tool is permitted.

Docker source matching observed server `d3298094ac5111e5d67517a252d291d27543e408` uses `daemon/export.go` → go-archive0.2.0 chroot tar on the mounted rootfs. That archive path emits final inode modes/UID/GID, symlinks, hardlinks and positive `security.capability` PAX values. However `ReadSecurityXattrToTarHeader` discards `lgetxattr` errors: an omitted capability header CANNOT prove absence. Capture reports positive headers verbatim/base64 with bounded decoding; omitted/error-ambiguous capability state stays UNKNOWN. Different/unreviewed engine/export behavior must not silently inherit this source qualification. No package or tool is installed to work around missing facts.

## Data collection

Parse the final tar as data with no filesystem archive extraction API. Require canonical image-relative paths, bounded regular-file sizes, unique entries, nonnegative numeric fields and expected supported tar/PAX forms. Retain special-file metadata but never create devices/FIFOs/links. Resolve symlink/hardlink chains only inside the virtual inventory with a depth bound; cycles, missing targets, unsupported sparse records, unexpected whiteouts, truncation or malformed metadata make the affected evidence incomplete. No host path follows an image link.

The full path inventory records type, mode including SUID/SGID, UID/GID, size, link target, positive capability/PAX provenance, regular-file SHA256 and first-byte format classification for every file. This captures same-name variants anywhere, hardlinks and byte-identical renamed copies. Compare all file hashes to reference hashes for removed original binaries from their typed historical layers or independently authenticated exact Debian packages. A modified/stripped/renamed binary is NOT excluded merely because it differs from a known hash. List all ELF and archive candidates. Uninspected nested archives, packed code, unsupported aliases or compiled/modified copies remain explicit gaps; filename or dynamic-symbol absence is never blanket code-absence proof.

Retain raw bounded `/var/lib/dpkg/status`; relevant `.list` and `.md5sums` records for zlib1g, perl-base, ncurses-bin/base/libtinfo6, util-linux/bsdutils/mount/login and its libraries, gcc-14-base/libgcc-s1/libstdc++6, libc6/libc-bin, libacl1; applicable copyright/source references and `/etc/fstab`. These are public image data, not host files. Do not upload Env values, arbitrary app data, credentials, the full image/rootfs archive or unspecified file contents.

Select all matching final paths and aliases for infocmp, nsenter/nsenter.static, mount/umount/mount helpers, getfacl/setfacl/chacl, Perl Pod/Text.pm and Pod/Text/{Color,Overstrike,Termcap}.pm, Archive/Tar.pm; libc/libresolv/libstdc++/libgcc_s/libz/libacl/libmount/libblkid/libuuid; Node and every installed native `.node` object. Record all copies under any prefix, including `/usr/local`, `/opt`, app modules and alternate lib directories. Keep an archive-location ledger; bounded nested parsing can be a separately reviewed follow-up when the first inventory shows relevant containers, never a silent assumption of absence.

For selected ELF bytes, write only opaque content-hash filenames into private scratch with mode0600, never image paths or executable permissions. Use an already present, reviewed trusted host `/usr/bin/readelf` as a data parser: record actual binary path/hash, version and help; no install or implicit fallback. Run bounded `--file-header --program-headers --dynamic --notes --dyn-syms --wide --no-demangle` with fixed locale/empty private HOME and `DEBUGINFOD_URLS` empty, no shell, external debug lookup or process loading. Preserve complete stdout/stderr/exit and input SHA per object; output limits or unsupported options mean incomplete evidence. Capture ELF architecture, interpreter, DT_NEEDED, RPATH/RUNPATH, GNU buildID, versioned imports/exports and native-object hashes. Retain literal symbol names; dynamic-symbol absence does not exclude static/stripped/compiled-in functions, and DT_NEEDED is not actual runtime resolution. Resolve library paths only against the captured filesystem, label ambiguous loader search or dlopen as unresolved. No disassembly or target execution is required for the first evidence slice.

Proposed conservative bounds: existing target admission1GiB unchanged; export ≤1GiB+128MiB and60s; tar stream ≤1GiB regular payload,100000 entries and60s; inventory/report ≤32MiB; selected scratch ≤256MiB total/128MiB per object; each readelf process ≤5s and8MiB combined output, total ELF phase≤60s. Capture overall≤180s including reserved30s cleanup, separately from the unchanged scanner step. These are proposal caps, not measured success: fail as incomplete when exceeded, never raise limits automatically or truncate into an absence/clean claim. Artifact retention is `always()` even if scan or capture fails. Raw scanner enforcement remains independently unchanged.
