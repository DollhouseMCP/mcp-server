The production audit reports three moderate entries, all from `qs@6.16.0`; standalone Safety reports six low entries from the Jest/deepmerge chain. The earlier lock-only audit returned 12 entries because it omitted some propagated qs parent entries; it is not substituted for the installed result.

- **Inspector/Zod:** replace the umbrella Inspector development dependency with exact official `@modelcontextprotocol/inspector-cli@0.21.1`. Its 11 compiled CLI files are byte-identical to the CLI previously supplied by the umbrella; its February 27 publication exceeds 21 days. npm regenerates the lock without lifecycle scripts, removing 127 orphan records and changing no retained version or integrity. All four nested `zod@3.25.76` copies and the old browser assets disappear. Merely overriding Zod would leave vulnerable code embedded in the prebuilt UI. The npm `inspector` and `inspector:dev` GUI convenience commands are removed explicitly. The obsolete GUI QA runner refuses with instructions to use `qa:all`, and the dashboard names that supported runner. Hosted behavior is unaffected; `qa:direct` and the existing external `qa:inspector` entry point retain all three MCP modes.
- **qs:** exact 6.16.1 is the smallest fix for [GHSA-6pq8-jhm2-2vcw](https://github.com/advisories/GHSA-6pq8-jhm2-2vcw). The existing global 6.16.0 override also forces body-parser 2.4.0 below its raw ^6.16.1 requirement. Mick approved the exact 6.16.1 age exception on October 28 subject to provenance qualification; that qualification is complete and the exact override is adopted. No 6.17.0 adoption is included. Current Express/body-parser use `qs.parse`, while the reported vector requires `qs.stringify` with comma arrays and an own non-callable `toString`; the incoming 6.16.0 dependency was affected even without an observed hosted call to that option.
- **Custom scanner DMCP-SEC-006:** the config installer previously performed persistent client launch-config writes without a security audit event. It now emits `CONFIG_UPDATED` after the awaited atomic write and a fixed `OPERATION_FAILED` envelope on refusal/failure, then rethrows. No config content, local path, raw parser error or unvalidated request value enters the event. Per-attempt random IDs prevent the monitor's 60-second deduplication from erasing separate installs. Manual Warp instructions do not report a write. No suppression is added; the custom scanner now reports zero findings.
- **deepmerge:** [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4) is a real low development-only finding in root and standalone Safety. A bounded reproduction confirms an inherited property on the returned merged object, without global Object.prototype pollution. The only parent is Jest's config/default/global merge (`jest -> @jest/core -> jest-config -> deepmerge`), and production excludes it. Latest upstream deepmerge is still 4.3.1 with no patched version; latest jest-config still requires it. A Jest 25 downgrade or incompatible library alias is unsuitable. [Issue #3166](https://github.com/DollhouseMCP/mcp-server/issues/3166) tracks remediation. Mick accepted this real LOW development-only residual for beta.3 only, conditional on clean final production and packed-consumer audits. Both final audits are clean. The finding remains reported and tracked, rather than fixed or suppressed.

## Zod reachability limits

The root direct Zod 4.6.7 package retains its `/v3` compatibility export. A bounded constrained-array test still emits 21 issues for 20 invalid v3 items with max(1), versus one issue for v4; `/v3` is not represented as patched. Repository schema imports resolve to v4. SDK 1.32.0 protocol/auth imports explicitly use `zod/v4`, and all 152 inspected exported protocol schemas are v4. Inspector CLI creates no own Zod schemas, uses SDK default v4 result schemas, and validates remote JSON Schema through AJV. SDK compatibility can dispatch to v3 if supplied a legacy JavaScript schema, but no such schema input was found in these application/CLI paths. Stdio protocol parsing uses v4 with a 10 MiB wire buffer. These observations justify removing the active old Inspector closure; they do not claim that every latent validator implementation or arbitrary unbounded schema is safe.
