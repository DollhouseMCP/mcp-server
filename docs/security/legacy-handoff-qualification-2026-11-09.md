The current verified memory-drain gate remains required. The legacy image below has no demonstrated way to attest that accepted memory work has settled before replacement. This record does not authorize a handoff, a host change, or an override of the v2 gate.

The hosted `DEPLOYED_REVISION` marker is not evidence of the image source.

The bounded [compiled fragment record](../../tests/fixtures/legacy-handoff/compiled-methods.json) has SHA-256 `30941ff7c199739f8f976294295a0a55a530f8c4bd013dda69fd8f90aa6bfc5d`. It records the full extracted-file hashes, exact line ranges, fragment hashes, and original compiled bytes. Those bytes and hashes were compared to the locally retained archive extraction. The original archive and extraction are retained outside this repository; the image was not run as part of this qualification. The local witness used Node 24.16.0; the image reports Node 24.21.0.

The [portable regression](../../tests/scripts/legacy-handoff-counterexample.test.mjs) executes those exact compiled fragments with a controlled timer, memory manager, session and HTTP server in a disposable child process. The archived signal fragment calls that child’s real `process.exit(0)`. It demonstrates a possible sequence where an append returns a receipt, session cleanup leaves its deferred save pending, and the archived HTTP signal path reaches exit zero. It also demonstrates that a timer-started save can leave the pending map before the asynchronous save completes; the archived pending-map flush can then return while that save remains in flight. The queued-save control verifies that the same flush waits when work is still in the map. The witness selects the ordinary legacy deferred-save branch (`origin.bindingCheck` is absent and deferred refusal is false), using controlled manager and origin doubles. The empty-pending-map case applies specifically to that timer branch. It does not establish full authenticated origin binding or the current host storage profile. The transport, session services, memory manager and timer are test doubles; this is a control-flow counterexample, not a whole-image or native-container qualification.

Separately, the image's storage cleanup can cancel a pending debounced `_index.json` write; that index is derived data and this does not by itself establish primary memory loss. The observed host's pending work and any actual data loss are unknown. The current helper's regression confirms that a legacy profile without the v2 capability is refused before Docker exec or TERM. No production admission, shutdown, or replacement behavior changes in this record.

A future handoff needs independently verified admission fencing and a trustworthy way to establish settlement of accepted work and failures for the exact running image and boot, plus qualified lifecycle behavior. No such legacy settlement observable has been established here.

For the separate, unqualified one-time persisted-checkpoint and recovery plan, see the [legacy maintenance checkpoint guide](../guides/legacy-maintenance-checkpoint.md).
