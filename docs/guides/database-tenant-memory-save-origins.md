# Deferred memory operation origins

This caller plumbing remains dormant. The composed AQL handler owns one MemorySaveHandler per actual selected manager; each dispatch supplies the synchronous check minted by its authenticated provider operation. Configured handlers require that check before discovery or mutation. No shared handler field stores a current invocation.

Each pending or failed save retains its actual manager, exact originating ExecutionContext and original binding check. Timers, shutdown flush and failure-ledger replay restore that origin and check it before lookup/probing/writing and after awaited work. A later request cannot lend its context or authority to an earlier retained candidate. A new append checks the earlier pending origin before using its authoritative RAM instance; the authoritative retained record is re-read after acquiring mutation serialization and its earlier origin is checked synchronously again immediately before applying/coalescing the new append, and an earlier failed save is retried in its own context before new entries are accepted. Context restoration or binding refusal retains the candidate and bookkeeping. Confirmed deletion cannot remove failed evidence after its original binding ceases to be valid.

Checks after discovery and candidate validation precede RAM append application. Checks after a save preserve evidence if the origin changes while that save is already running; they do not claim cancellation or rollback. Guarded deferred work remains refused by the existing monotonic latch. Immediate guarded mutations retain their own original binding through candidate validation, conditional save and owning publication. Synchronous diagnostics/deletion bookkeeping in composed mode require an authentic pre-resolved operation check from the caller plumbing.

Composed LEGACY clear refuses before mutation while pending/failed sole-copy work exists; it must be resolved or successfully drained first. This refusal re-reads the maps after waiting for preceding mutations, before cancelling any timer or changing RAM. Immediate guarded clear continues its independent candidate-based path.

Ordinary fixed-manager constructors remain supported without provider binding; existing context-less/debounced behavior and failure-ledger semantics remain. This process-local queue is not durable candidate handoff, a cross-process liveness fence, global shutdown exclusion or final production registration. Activation still requires complete route/refuse coverage, cold writer/process exclusion, pending-work drain and the applicable durable boot/handoff qualification.
