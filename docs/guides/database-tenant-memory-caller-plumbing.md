# Tenant-bound memory caller plumbing (dormant slice A)

This slice provides a trusted async operation provider and explicit ElementCRUDHandler call-site plumbing. It does not register a provider in production, qualify owners, enable storage, or establish shutdown/cold-promotion exclusion. It depends on the private registry/startup contract in #3029 under #2998.

At public caller entry, the provider synchronously captures the actual trusted effective database tenant/opaque registry slot and original ContextTracker invocation/session references and copied primitives. It awaits that exact initialization flight, rechecks the original binding, and returns one resolved MemoryManager plus a synchronous binding check. The configured handler requires an actual provider and the same actual ContextTracker; missing/structural providers cannot reinterpret a supplied fixed manager as fallback. Neither clients nor a request field can choose a replacement manager. No promise is passed as a manager and no manager is reselected during the operation.

Configured CRUD, list/details/reload, policy/deadlock and memory/ensemble activation use a private per-invocation handler bound to that manager. The handler retains the original binding check locally; no mutable current request/session is stored in shared handlers. Only the existing overlapping policy snapshot cache is shared within the same parent handler, actual manager and session scope. Bound helpers use the same manager. Ordinary fixed-manager constructors and behavior remain supported. Configured handlers do not create memory/ensemble strategies from a supplied cached root manager or fall back when capture/initialization fails.

AgentManager.executeAgent independently reads memory through its existing cached resolver; continueAgentExecution is conservatively grouped with it. Configured and bound handlers explicitly refuse both before AgentManager effects until a trusted caller seam is implemented. Agent activation and ensemble agent members currently use activateAgent/status, not executeAgent/getElementContent; ensemble memory members receive the selected manager. Direct AgentManager resolver composition remains a required production-wiring inventory item.

Checks occur before selection, after initialization, when bound context/manager/session helpers are accessed and before the final result is delivered. They are not cancellation of already-started asynchronous work and do not establish rollback if a context changes after an effect. Original operation errors are preserved. Provider failure observation is redacted and best-effort; observer failures cannot replace the original rejection.

Local controls use the actual registry, actual managers/Container services and ContextTracker, with controlled DB transport and selected read/activation boundaries. They cover same/different tenant entries, forged captures, drift while initialization/body awaits, no fixed-manager read, real memory/ensemble strategy manager binding, agent-path refusal policy coalescing isolation and separate actual session activation sets despite same-tenant manager sharing. A required owned-PostgreSQL case traverses actual CRUD discovery and memory activation using two explicit legacy tenant entries and verifies all memory heads and fixture data remain unchanged; already-initialized infrastructure is isolated from final boot composition. Authored PostgreSQL is not executed proof until current-head CI assertions/cleanup complete.

Remaining slices are AQL/console/deferred origin retention (B) and actual Container/registrar/static/background wiring (C), including direct agent memory lookup. Final production composition must prove all reachable selected-tenant paths route or refuse, preserve request attribution through awaited owning tails, and enforce closed boot/quota/owner eligibility. Cold all-replica writer/account/admin exclusion, pending-work drain, backup/restore/rollback and the capacity/oversized-load/two-authenticated-session/restart proofs remain required. No live action is authorized by this source slice.
